# 摘要索引缺少 Prompt 时使用系统默认 Prompt

当摘要索引已启用但 `summary_prompt` 为空时，兼容历史配置并使用系统默认 Prompt，而不是在节点数据校验阶段失败。这样可以保留用户已开启的摘要索引行为，并复用现有摘要生成逻辑中的默认 Prompt；同时，索引任务中的其他异常仍必须将文档标记为错误，不能继续显示为排队状态。

## Considered Options

- 判定配置错误：会使历史配置无法继续索引。
- 自动关闭摘要索引：会静默改变用户配置语义。

## Consequences

- 节点数据校验必须允许缺少或为空的 `summary_prompt`。
- 需要用回归测试覆盖空值、缺失和有效 Prompt 三种配置。
- Pipeline 执行失败时，文档标记为 `error`，由用户显式发起重试，不自动重试。
- 当前已卡住的目标文档只做一次范围限定的 `waiting` 到 `error` 状态修复，再由用户手动重试；不批量扫描或修改其他文档。
- 发布版知识库 Pipeline 的所有执行异常都按租户、知识库、Pipeline 和文档 ID 校验后回写为 `error`，不扩展到普通 Workflow 执行。
- 文档只保存可展示的简化错误信息，完整异常堆栈仅记录在 Worker 日志中。
- 历史空 Prompt 只在运行时兼容，不通过生产数据回写或批量迁移改变 Workflow 配置。
