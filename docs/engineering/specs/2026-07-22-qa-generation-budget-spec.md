## Problem Statement

当前知识库创建页面在选择“使用 Q&A 分段”后，Q&A 生成模型的输出 token 预算无法由用户配置。此前为缓解 Q&A 预览为空而将生成器的全局预算临时提高到 `4096`，但这既改变了默认成本与响应行为，也不能满足不同文档按需调整预算的需求。

用户需要在 Q&A 分段场景中配置 Q&A 生成预算，并确保预览、首次创建、后续编辑和重新索引使用同一持久化值。该预算必须与文本分段长度保持语义独立，默认值恢复为 `2000`。

## Solution

在知识库创建与文档配置界面中，仅当选择“使用 Q&A 分段”时显示 Q&A 生成预算输入。输入沿用现有 max_tokens 数字输入的操作体验，默认值为 `2000`，最小值为 `1`，最大值与现有知识库分段上限配置保持一致。

将该配置作为处理规则中的专用 Q&A 生成设置持久化，使用 `qa_generation.max_tokens` 表达其语义。预览请求和正式创建请求传递同一份处理规则；异步索引、编辑和重新索引从已持久化的处理规则读取该值并传入 Q&A LLM 调用。缺少该设置的历史规则和未显式设置的调用一律回退到 `2000`。

## User Stories

1. 作为知识库创建者，我希望仅在选择“使用 Q&A 分段”时看到 Q&A 生成预算配置，以便不会把它误认为普通文本分段长度。
2. 作为知识库创建者，我希望 Q&A 生成预算默认是 `2000`，以便不需要每次手动填写常规值。
3. 作为知识库创建者，我希望能通过现有数字输入的直接输入和增减控件修改预算，以便沿用熟悉的交互方式。
4. 作为知识库创建者，我希望输入值不能小于 `1` 或大于当前知识库分段上限，以便避免提交无效或超出平台限制的预算。
5. 作为知识库创建者，我希望从 Q&A 分段切换到其他分段方式后再切回时保留本次输入的预算，以便不丢失已完成的配置。
6. 作为知识库创建者，我希望点击 Q&A 配置区域的“重置”后预算恢复为 `2000`，以便快速撤销本次修改。
7. 作为知识库创建者，我希望点击预览时使用当前配置的预算，以便预览结果能够代表正式创建时的行为。
8. 作为知识库创建者，我希望正式创建文档时使用与预览相同的预算，以便避免预览可生成而实际索引失败或结果显著不同。
9. 作为知识库管理员，我希望 Q&A 生成预算随处理规则保存并关联到文档，以便后续编辑和重新索引可复用原始配置。
10. 作为知识库管理员，我希望历史处理规则中没有 Q&A 生成预算时仍能正常索引，以便旧知识库不因新增配置而失效。
11. 作为平台维护人员，我希望 Q&A 生成预算与文本分段长度分别建模，以便后续调整其中一项不会意外改变另一项的语义。
12. 作为平台维护人员，我希望默认 LLM 调用恢复为 `2000`，以便不再将先前的 `4096` 临时修复作为全局默认行为。
13. 作为测试维护人员，我希望从请求参数和 LLM 调用参数观察配置传播，以便回归测试保护真实业务契约而不是内部组件实现细节。

## Implementation Decisions

- 在处理规则的 `rules` 对象中新增专用的 `qa_generation` 设置，其中 `max_tokens` 表示 Q&A 生成模型单次非流式输出的 token 上限；该字段不得复用或覆盖 `segmentation.max_tokens`。
- 前端处理规则类型、后端请求 DTO、后端处理规则实体与持久化 JSON 采用同一字段结构，保证预览、创建、编辑和重新索引可无转换歧义地使用该值。
- Q&A 分段的页面状态独立于普通文本分段状态维护；切换分段模式不重置该状态，Q&A 配置区域的重置操作才将其恢复为 `2000`。
- Q&A 生成预算输入仅在 Q&A 分段被选中时渲染，使用既有数字输入组件的增减控件、最小值和上限策略；用户可见文案通过现有国际化资源提供。
- 预览和正式创建复用同一份已组装的处理规则。服务端应将该规则保存为文档关联的处理规则，后续异步索引、编辑和重新索引从同一持久化规则读取 Q&A 生成预算。
- Q&A 索引处理器从处理规则中读取 `qa_generation.max_tokens` 并显式传入 Q&A 文档生成器；生成器方法支持该预算参数。
- 当请求、持久化规则或生成器调用未提供 Q&A 生成预算时，默认值固定为 `2000`。历史处理规则保持可读，不执行数据库迁移或批量回填。
- 服务端对请求的 Q&A 生成预算执行正整数与平台上限校验，防止绕过页面约束提交无效值。
- 不改变 Q&A Prompt、模型选择、温度、Q&A 解析格式、文本分段策略、向量写入或 Q&A 预览响应结构。

## Testing Decisions

- 已确认采用一个最高层测试 seam：同一 Q&A 生成预算在预览请求、正式创建请求和后端 Q&A LLM 调用中一致可观察；测试不直接断言 React 内部 state、私有辅助方法或线程实现。
- 前端覆盖 Q&A 模式下默认值、显示条件、范围约束、切换后保留、重置回默认值，以及预览和创建请求携带同一 `qa_generation.max_tokens`。
- 后端覆盖处理规则 DTO 的接受与校验、规则 JSON 的持久化与重新读取、缺失字段回退到 `2000`，以及自定义值从 Q&A 索引处理器传递到 LLM 调用。
- 覆盖生成器的两个外部行为：未提供预算时向模型传递 `2000`；提供自定义预算时向模型传递该自定义值。
- 复用现有创建页预览 hook、创建 hook、Q&A 索引处理器和 LLM 生成器的定向测试基础；每个断言以请求体或模型调用参数为边界。
- 执行对应前端单元测试与后端定向 pytest；测试报告必须区分定向测试、静态检查和未执行的完整测试套件。

## Out of Scope

- 将 Q&A 生成预算暴露给非 Q&A 分段模式。
- 修改普通文本分段长度、分隔符、重叠长度或父子分段配置。
- 调整 Q&A Prompt、模型提供商、默认模型选择、温度、解析规则或向量索引策略。
- 修改已有知识库的历史规则、执行批量数据迁移或回填数据库。
- 部署、远端模型配置、生产数据修复和以原始文档进行认证后的业务验收。
- 变更 Q&A 预览接口的返回字段或将空预览业务提示改造成新的错误协议。

## Further Notes

- `4096` 是此前用于缓解预览为空问题的临时全局行为；本规格要求默认值恢复为 `2000`，由用户按文档需要提高预算。
- Q&A 生成预算的配置传播必须覆盖预览与正式索引两条独立请求路径；仅修改预览路径不满足本规格。
- 当前仓库未配置可用的项目 issue tracker，因此本规格作为正式状态源；后续如配置 tracker，应同步发布并标记为 `ready-for-agent`。
- 规格已获得用户对测试 seam 的确认。下一阶段需要先完成 tracer-bullet ticket 的粒度和依赖关系确认，之后才能发布本地 tickets。
