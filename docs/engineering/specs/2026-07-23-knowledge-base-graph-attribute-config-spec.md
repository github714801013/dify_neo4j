# Pipeline Knowledge Base 节点图谱属性配置规格

**本地状态：** `ready-for-agent`。

## Problem Statement

知识库 Pipeline 的 Knowledge Base 节点目前只能承载文本分块、普通索引及摘要索引相关配置，不能在节点级别声明图谱实体类型、关系类型、允许三元组以及实体和关系的属性。运营人员因此无法按具体 Pipeline 的业务语义控制图谱抽取字段；图谱抽取结果也无法以可校验、可追溯的方式写入 Neo4j 的 `GraphEntity` 与 `GraphFact`。

现有数据集级 GraphRAG 配置不能解决该问题：它不是节点特定配置，不能表达“仅对经过某个 Knowledge Base 节点的文档生效”的边界，也不应被节点配置隐式合并、复制或回写。与此同时，图谱抽取、插件调用或 Neo4j 写入失败不得影响文本分块、普通向量索引和 Knowledge Base 节点的正常输出；否则新增图谱能力可能再次表现为分块为空或文档主索引失败。

## Solution

为 Pipeline Knowledge Base 节点增加唯一正式 DSL 字段 `graph_index_config`，以结构化表单配置节点级图谱索引与抽取规则。该字段保存图谱开关、抽取模型引用、完整 Schema（实体类型、关系类型、允许三元组以及各类型属性定义）和系统生成的图谱版本；不承载任何图谱检索运行时参数。

节点存在有效 `graph_index_config` 时，它是该节点图谱抽取的唯一权威配置，只影响实际经过该节点的文档；节点未配置时继续保留既有数据集级 GraphRAG 行为。配置保存只更新 Pipeline DSL，后续由独立图索引协调器和 Reconciler 异步、分批重建符合条件的历史文档。图谱任务使用独立队列和失败边界，图谱失败只形成任务重试、失败记录或结构化告警，不阻断文本分块、向量索引或节点输出。

抽取端要求 LLM 将实体和关系属性放在嵌套 `properties` 对象中。系统严格按照节点 Schema 校验属性，写入时将实体属性保存到 `GraphEntity`、关系属性保存到 `GraphFact`，并将物理 Neo4j 属性键统一映射为 `attr_<logical_name>`。未声明、可选缺失或类型无效的属性被丢弃；必填属性缺失或无效时只跳过对应实体或关系记录，不使整个 Segment 或图索引任务失败。

## User Stories

1. 作为知识库管理员，我希望在 Pipeline 的 Knowledge Base 节点配置图谱索引，以便同一数据集中的不同文档流程可以使用不同图谱抽取语义。
2. 作为知识库管理员，我希望节点图谱配置使用正式字段 `graph_index_config`，以便 DSL 消费方只有一个明确契约。
3. 作为知识库管理员，我希望系统不接受 `graph_rag_config` 别名，以便避免两个字段产生优先级和迁移歧义。
4. 作为知识库管理员，我希望未配置节点图谱字段时保持原有数据集级 GraphRAG 行为，以便历史 Pipeline 不因新增能力改变结果。
5. 作为知识库管理员，我希望节点已配置图谱字段时不与数据集级配置合并，以便节点配置可以独立、可预测地控制抽取。
6. 作为知识库管理员，我希望节点配置只作用于实际经过该节点的文档，以便图谱数据的来源范围符合 Pipeline 业务边界。
7. 作为知识库管理员，我希望图谱配置页面只出现索引和抽取选项，以便不误把检索运行时调优当成节点处理配置。
8. 作为知识库管理员，我希望通过结构化表单维护实体类型、关系类型和允许三元组，以便无需编辑任意 JSON。
9. 作为知识库管理员，我希望为每个实体类型配置独立属性，以便不同实体具有符合业务语义的字段。
10. 作为知识库管理员，我希望为每个关系类型配置独立属性，以便事实记录可以携带来源、金额、状态等关系语义。
11. 作为知识库管理员，我希望属性可以填写自然语言描述，以便模型准确理解需要抽取的业务字段。
12. 作为知识库管理员，我希望属性名受到小写 `snake_case` 校验，以便 DSL、模型输出和 Neo4j 物理键保持稳定。
13. 作为知识库管理员，我希望属性值类型只限于单值的字符串、数字、布尔值和日期，以便图谱数据可校验且易于检索。
14. 作为知识库管理员，我希望必填属性未抽取到时只跳过该实体或关系，以便一条不完整记录不会丢弃同 Segment 的其他有效图谱信息。
15. 作为知识库管理员，我希望关闭图谱开关后可以只保存 `{ "enabled": false }`，以便快速停止后续抽取而不被 Schema 或模型字段阻塞。
16. 作为知识库管理员，我希望关闭图谱开关后保留此前 Schema 和图数据，以便稍后重新启用时不丢失配置或历史审计信息。
17. 作为知识库管理员，我希望启用图谱时只能选择当前租户已经配置的模型，以便不保存密钥，也不产生无法执行的模型引用。
18. 作为知识库管理员，我希望系统生成且只读的 `graph_version`，以便配置变化能可靠地驱动可控重建。
19. 作为知识库管理员，我希望保存 Pipeline 时不同步扫描所有历史文档，以便配置保存保持快速且不会突然产生大量任务。
20. 作为知识库管理员，我希望系统异步、分批重建曾实际经过该节点的已完成文档，以便配置变更最终覆盖历史数据且可限流。
21. 作为知识库管理员，我希望实体和关系属性分别写入既有 `GraphEntity` 与 `GraphFact`，以便保留系统已有的版本隔离、证据链和事实模型。
22. 作为知识库管理员，我希望系统不按用户关系类型创建动态 Neo4j 关系，以便避免 Schema 膨胀和绕过现有事实唯一键。
23. 作为知识库管理员，我希望未在 Schema 中声明的模型属性被忽略，以便模型额外输出不会污染图数据库。
24. 作为知识库管理员，我希望系统不对字符串做隐式数值、布尔或日期转换，以便不正确的模型输出不会伪装成有效业务数据。
25. 作为知识库管理员，我希望同一图节点或事实出现冲突的合法属性值时系统不任选一个写入，以便避免最后写入覆盖造成错误事实。
26. 作为知识库管理员，我希望属性冲突和丢弃原因形成结构化告警，以便排查模型质量而不影响主索引可用性。
27. 作为知识库使用者，我希望图谱抽取或 Neo4j 故障时文本分块和向量索引仍然成功，以便仍可使用知识库的普通检索能力。
28. 作为知识库使用者，我希望图谱任务失败后文档不会因为图谱依赖而产生空分块，以便主索引结果真实反映文档处理情况。
29. 作为平台维护人员，我希望图谱失败使用独立重试与失败状态，以便能够定位外部插件、网络和 Neo4j 问题而不回滚主索引。
30. 作为平台维护人员，我希望配置校验失败时 Pipeline DSL 保持原值，以便无效保存不会破坏已生效的节点配置。
31. 作为平台维护人员，我希望历史 DSL 不需要批量迁移，以便发布新字段后旧 Pipeline 仍可运行。
32. 作为测试维护人员，我希望从 DSL 请求、节点输出、协调器任务与 Neo4j 写入参数观察行为，以便回归测试保护外部契约而非私有实现细节。
33. 作为测试维护人员，我希望能够单独模拟图谱抽取和写入失败，以便验证普通分块和向量索引不会被新能力阻断。
34. 作为安全维护人员，我希望节点 DSL 只保存模型提供商、模型标识和非敏感参数，以便图谱配置不泄露模型凭据。
35. 作为后续功能开发者，我希望日期属性使用 Neo4j 原生 `date`，以便以后新增日期时间类型时不会改变当前日期语义。

## Implementation Decisions

- Pipeline Knowledge Base 节点新增可选的 `graph_index_config`；该字段是正式且唯一的节点级图谱索引 DSL 字段，不实现 `graph_rag_config` 兼容别名。
- `graph_index_config` 仅包含图谱抽取与索引所需内容：`enabled`、系统生成的 `graph_version`、完整 `schema` 与非敏感 `extract_model_config`。不包含 `query_mode`、`graph_top_k`、`graph_max_depth`、`graph_timeout_ms`、`graph_weight` 或其他检索运行时参数。
- 当字段缺失时，节点保持既有数据集级 GraphRAG 行为；当字段存在时，它是该节点唯一的图谱执行配置，不与数据集级配置合并、复制或回写。`enabled=false` 停止后续图谱抽取/写入，但保留 DSL 中其他图谱配置及已有 Neo4j 图数据。
- 启用配置必须同时提供有效 Schema 和租户已配置的抽取模型。模型选择复用现有租户模型可用性校验，只持久化 provider、model 及允许的非敏感参数，禁止保存密钥、凭据或自由输入的未配置模型。
- Schema 采用对象列表：`entity_types` 与 `relation_types` 的每项均包含 `name` 和 `properties`；`allowed_triples` 的每项使用 `source_type`、`relation_type`、`target_type`。属性定义包含 `name`、`description`、`value_type` 和 `required`，其中 `required` 默认为 `false`。
- 属性名必须为 1 至 64 位小写 ASCII `snake_case`，以字母开头，后续仅允许字母、数字和下划线；属性名在同一实体类型或关系类型中唯一。`description` 允许自然语言。
- `value_type` 只允许 `string`、`number`、`boolean`、`date`，且只支持单值标量。`date` 只接受合法的 `YYYY-MM-DD` 并写为 Neo4j 原生 `date`；本期不支持数组、对象、嵌套结构、时间、时区或 `datetime`。
- 前端复用现有检索设置的配置布局、表单校验和模型选择交互，但图谱 Schema 与属性必须由结构化控件编辑。用户可添加、删除和编辑实体类型、关系类型、允许三元组及类型属性；用户不可编辑原始 Schema JSON、`graph_version` 或模型凭据。新增界面文案通过现有国际化资源提供。
- Pipeline 保存路径在持久化前校验完整节点 DSL。无效 Schema、非法模型引用、非法属性名、重复名称、无效允许三元组或非法属性类型必须拒绝本次保存，并且不能覆盖旧 DSL 配置。
- 系统使用影响抽取结果的规范化节点图谱配置生成稳定 `graph_version` 指纹。Schema、属性定义、抽取模型或其他影响抽取输出的非敏感配置改变时产生新版本；前端不得手工指定版本。
- 图谱任务保持独立图索引协调器、Reconciler、任务表、队列与 Adapter 边界。保存 DSL 不同步扫描或大批量投递任务；Reconciler 异步、分批处理实际经过该节点的完成文档，并按新的 `source_version + graph_version` 创建幂等重建任务。
- 任务调度和重建范围必须携带足够的节点执行来源信息，确保不会把未经过该 Knowledge Base 节点的文档纳入节点级配置的重建范围。任务幂等、超时恢复、删除/归档清理和独立队列原则保持既有 GraphRAG 计划约束。
- 抽取协议要求实体项与关系项的属性均位于嵌套 `properties` 对象；实体仍包含其名称和类型，关系仍包含来源、目标和关系类型等固有字段。抽取器只接受已声明属性，未声明属性直接丢弃。
- 属性校验严格且不做隐式字符串转换：`string` 必须为非空 JSON 字符串；`number` 必须为有限 JSON 数值；`boolean` 必须为 JSON 布尔值；`date` 必须为合法 `YYYY-MM-DD`。空字符串、无穷数、类型不匹配和非法日期均视为未抽取到。
- 缺失或无效的可选属性直接丢弃。缺失或无效的必填属性时跳过对应实体或关系；同 Segment 的其他有效记录继续处理，图索引任务不因该记录失败。
- 实体属性写入 `GraphEntity`，关系属性写入 `GraphFact`；不新增实体到实体的动态 Neo4j 关系类型。所有用户逻辑属性名在 DSL 和模型 JSON 中保持原样，Neo4j 物理属性键统一使用 `attr_<name>`，不得覆盖系统范围、版本、证据、文档、Segment 或时间戳字段。
- 同一 `GraphEntity` 或 `GraphFact` 的同一逻辑属性出现多个不同合法值时，不写该属性，记录包含节点、文档、Segment、类型、属性名与冲突值摘要的结构化告警；不得随机选值、最后写入覆盖或使整个任务失败。
- 图谱抽取、插件调用和 Neo4j 写入必须完全隔离于文本分块、普通向量索引和 Knowledge Base 节点输出。图谱阶段异常进入图谱任务的重试或失败记录，主索引继续完成；图谱失败不能导致分块为空、普通索引失败或节点把图谱异常作为主流程异常抛出。
- 仅为新增节点字段和必要执行来源/任务追踪增加可逆、独立的持久化变更；不批量迁移历史 DSL，不修改上游高频分段和文档表的既有数据语义。

## Testing Decisions

- 已确认采用以“Knowledge Base 节点到图索引协调器”的行为契约为最高可复用测试 seam。测试从节点 DSL 输入、主索引调用、协调器调度请求、任务状态和图写入参数观察外部行为，不断言 React 私有 state、私有辅助函数或具体线程实现。
- 前端定向测试覆盖：图谱开关；禁用时允许最小配置；启用时 Schema 与模型必填；实体/关系属性编辑；属性名与类型校验；允许三元组校验；只读版本；模型候选只来自已配置租户模型；保存请求包含 `graph_index_config` 且不夹带检索参数；保存失败时保留编辑前的已持久化配置。
- 节点与 DSL 测试覆盖：缺失字段回退到数据集级既有行为；存在字段时不与数据集级配置合并；别名字段被拒绝；节点配置仅随实际节点执行传播；保存与解析得到一致的规范化配置和稳定版本。
- 主要隔离回归测试覆盖：主索引收到原始有效分块并产生既有节点输出时，图索引协调器、插件或 Neo4j Adapter 无论成功、可重试失败还是最终失败，都不能改变分块、向量索引调用或节点成功结果。
- 抽取器定向测试覆盖：实体属性与关系属性的嵌套 `properties` 协议；未声明属性丢弃；四种合法值类型；空字符串、字符串化数字、字符串化布尔、无穷数、非法日期和数组/对象拒绝；可选属性丢弃；必填属性导致仅对应记录跳过。
- 图写入测试覆盖：实体属性进入 `GraphEntity`，关系属性进入 `GraphFact`；所有用户键被映射为 `attr_<name>`；日期作为 Neo4j `date` 参数；系统属性不被覆盖；不创建动态实体关系；同属性不同合法值不写入并产生结构化告警。
- 协调器与 Reconciler 测试覆盖：配置保存不立即全量扫描；历史完成文档按批次调度；只选择具有该节点执行来源的文档；相同 `source_version + graph_version` 不重复创建任务；配置影响抽取的变更创建新版本任务；禁用配置不产生新图谱任务且不删除既有图数据。
- 使用已有 Knowledge Index 节点单元测试、图索引抽取器/写入器/协调器单元测试和任务测试作为先例。需要真实数据库、向量存储或 Neo4j 的端到端测试保持为独立集成环境验证，不以本机跳过的集成测试替代定向单元测试证据。
- 每次实现须运行受影响的前端 Vitest、后端定向 pytest、格式/类型检查与 `git diff --check`；报告必须区分已通过定向测试、未执行的完整套件和需要真实插件/Neo4j 环境验证的项目。

## Out of Scope

- 在 Knowledge Base 节点中新增或调整图谱检索参数、图谱问答模式、检索权重、top-k、深度、超时或检索排序策略。
- 为兼容目的新增 `graph_rag_config` 字段、双字段合并规则或对历史 DSL 的批量迁移。
- 将数据集级 GraphRAG 配置自动复制到节点级配置，或把节点配置回写到数据集级配置。
- 自由输入模型、保存模型密钥、支持未配置模型供应商，或改变租户模型管理机制。
- 支持数组、对象、嵌套属性、多值属性、时间、时区、日期时间或任意 JSON Schema。
- 创建动态 Neo4j 实体关系类型，替代既有 `GraphFact` 的事实承载模型。
- 禁用节点图谱配置时删除已有图数据，或在保存配置请求中同步进行全量重建。
- 改造已有图谱检索、普通向量检索、Reranker、文本分块算法或现有数据集级 GraphRAG 功能。
- 直接追查和修复本轮新增能力之外的历史“文本分块为空”根因；本规格只要求新增图谱能力不得造成或放大该故障。
- 部署、生产数据回填执行、生产 Neo4j 凭据配置与真实业务文档的验收操作。
