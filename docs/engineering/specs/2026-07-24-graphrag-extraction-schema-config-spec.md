# GraphRAG 图谱抽取 Schema 默认值与知识库配置规格

- 日期：2026-07-24
- 状态：正式规格；本仓库未配置可用的项目 issue tracker，因此该文档是本需求的正式状态源。若后续接入 tracker，必须同步发布并添加 `ready-for-agent` 标签。
- 决策优先级：本规格补充并落实既有 GraphRAG 原始需求、Knowledge Base 节点图谱属性规格以及“解耦 GraphRAG 图检索与图谱抽取生命周期”ADR。若它们相互冲突，以本规格为准。

## Problem Statement

当前知识库的数据集设置把“启用 GraphRAG”与 LlamaIndex 图谱抽取混为同一能力：用户无法明确区分“是否用已有图数据参与检索”和“是否从文档继续抽取、建立或重建图数据”。同时，Knowledge Base 节点虽然已有可编辑的图谱 Schema 与实体属性能力，但数据集的普通文档缺少同等的、可配置的抽取模板，也没有在首次启用时提供适用于通用文档的初始实体类型、关系类型和允许三元组。

这会导致以下用户问题：

- 用户开启图检索时，不清楚是否会开始耗时、耗模型额度的图谱抽取；关闭时也不清楚已有图数据会不会丢失。
- 用户必须从空白 Schema 开始配置文档图谱，缺少可编辑的通用文档初始值。
- 用户无法在数据集级别配置图谱抽取模型、实体/关系属性和 LlamaIndex 抽取参数；普通文档与 Pipeline 节点的配置边界不清。
- 修改数据集配置后，无法判断已有节点、历史 DSL、重建任务和查询结果会如何变化。
- 抽取模型失效、重建进行中或重建失败时，系统可能静默换模、查询旧版本图数据或阻断非图谱检索，造成数据正确性与可用性风险。

## Solution

将数据集的 GraphRAG 能力拆分为独立保存、独立生效的两个设置：

1. **启用 GraphRAG**：仅控制图检索是否参与知识库检索，不触发 LlamaIndex 图抽取，不删除图数据；页面文案只描述图检索。
2. **启用图谱抽取/索引**：控制指定范围是否使用 LlamaIndex 抽取并写入图数据；该设置拥有抽取模型、可编辑 Schema、实体与关系属性、`temperature`、`max_tokens`、`max_triplets_per_chunk` 与 `strict`。

数据集首次启用图谱抽取/索引时，系统提供可编辑的通用文档 Schema 初始草稿，但不替用户选择模型。用户必须显式选择当前租户已配置且可用的文本生成模型，随后才能真正启用索引。数据集模板服务于普通文档；新启用的 Knowledge Base 节点会复制当时的数据集模板为独立的 `graph_index_config` 快照，之后不持续同步。

每次首次启用或改变抽取结果的配置时，系统为受影响范围生成新的稳定 `graph_version`，立即清理该范围旧图数据，并异步、分批重建历史文档。普通文档范围和每一个 Knowledge Base 节点范围必须隔离。图检索仅使用各范围中状态为“已就绪”的当前版本图数据；重建中或失败范围自动跳过，并向用户说明图检索结果可能不完整。任何图谱抽取失败都不得使文本分块、向量索引、节点输出或其他知识库能力失败。

## User Stories

1. 作为知识库管理员，我希望“启用 GraphRAG”只代表图检索开关，以便明确控制查询是否使用图数据。
2. 作为知识库管理员，我希望图检索开关与图谱抽取/索引开关分别保存，以便可以单独调整查询能力和建图能力。
3. 作为知识库管理员，我希望关闭图检索后已有图数据仍被保留，以便以后重新开启检索时无需无谓重建。
4. 作为知识库管理员，我希望在数据集设置中单独开启图谱抽取/索引，以便为普通文档建立图数据而不改变图检索开关。
5. 作为知识库管理员，我希望第一次开启图谱抽取/索引时看到通用文档 Schema 初始值，以便不用从空白表单开始。
6. 作为知识库管理员，我希望默认 Schema 只是可修改的初始草稿，以便可以按业务文档自行调整而不会被后续默认值覆盖。
7. 作为知识库管理员，我希望初始实体类型包含 `person`、`organization`、`location`、`event` 与 `concept`，以便快速覆盖常见文档主体。
8. 作为知识库管理员，我希望初始关系类型包含 `works_for`、`located_in`、`participates_in` 与 `related_to`，以便快速表达常见文档关系。
9. 作为知识库管理员，我希望初始允许三元组只包含已确认的通用组合，以便抽取结果受控而不过度泛化。
10. 作为知识库管理员，我希望默认不预置自定义属性，以便只在确有需要时增加属性约束。
11. 作为知识库管理员，我希望能为实体类型和关系类型编辑属性的名称、说明、值类型和必填性，以便抽取结果符合业务字段约束。
12. 作为知识库管理员，我希望属性约束与 Knowledge Base 节点使用完全一致的命名、类型和 Neo4j 写入规则，以便数据集与节点的图数据可一致理解。
13. 作为知识库管理员，我希望自己显式选择租户内可用的抽取模型，以便控制成本、能力和合规性。
14. 作为知识库管理员，我不希望系统自动选择“第一个可用模型”，以便避免无意使用错误模型或供应商。
15. 作为知识库管理员，我希望配置 `temperature`、`max_tokens`、`max_triplets_per_chunk` 和 `strict`，以便针对不同文档平衡稳定性、成本与抽取量。
16. 作为知识库管理员，我希望首次草稿使用安全默认抽取参数，以便只需选择模型即可得到可预测的基础行为。
17. 作为知识库管理员，我希望未启用时可以保存不完整草稿，以便分步完成较复杂的 Schema 配置。
18. 作为知识库管理员，我希望真正启用时获得模型、实体类型、关系类型与允许三元组的字段级错误，以便准确修正配置。
19. 作为知识库管理员，我希望无效启用不会创建版本或开始重建，以便避免产生错误图数据和额外成本。
20. 作为知识库管理员，我希望保存影响抽取结果的配置后立即看到新的范围状态，以便知道重建已经异步开始而不是等待页面阻塞。
21. 作为知识库管理员，我希望重建前旧图数据仅在受影响范围内立即清理，以便不会查询到与当前 Schema 或模型不一致的结果。
22. 作为知识库管理员，我希望普通文档图数据与每个 Knowledge Base 节点图数据严格隔离，以便一个节点的重建或关闭不会误删其他范围的数据。
23. 作为知识库管理员，我希望同一范围连续保存新配置时只处理最新版本，以便过期任务不能写回旧配置的结果。
24. 作为知识库管理员，我希望重建任务可幂等重试并能恢复中断任务，以便 Worker 故障不会使范围永久卡住。
25. 作为知识库管理员，我希望配置的模型后来不可用时系统不自动换模，以便不会在未知模型上产生不可审计的图数据。
26. 作为知识库管理员，我希望模型失效后已就绪图数据仍可检索，以便查询能力不会因未来抽取不可用而无故丢失。
27. 作为知识库管理员，我希望模型失效时新的抽取、重建和影响抽取结果的保存被阻止并提示重新选模，以便显式恢复正确配置。
28. 作为知识库管理员，我希望关闭图谱抽取/索引立即停止后续抽取、删除该范围图数据并使其退出图检索，以便明确撤销该范围图数据。
29. 作为知识库管理员，我希望重新开启图谱抽取/索引后使用当前配置全量重建，以便不会复用已经删除或过期的结果。
30. 作为知识库管理员，我希望图检索在部分范围重建中或失败时仍使用其他已就绪范围，以便获得尽可能完整且正确的结果。
31. 作为知识库管理员，我希望看到每个普通文档范围和节点范围的图谱状态以及“图检索结果可能不完整”提示，以便正确解读查询结果。
32. 作为 Pipeline 作者，我希望新启用的 Knowledge Base 节点从当前数据集模板取得独立初始 `graph_index_config`，以便快速开始且可针对节点单独调整。
33. 作为 Pipeline 作者，我希望已有显式节点配置不被数据集模板修改覆盖，以便已发布流程的抽取契约稳定。
34. 作为维护历史 DSL 的 Pipeline 作者，我希望缺少 `graph_index_config` 的节点继续沿用数据集级行为，以便不需要批量迁移历史工作流。
35. 作为 Pipeline 作者，我希望节点 DSL 不包含图检索运行参数，以便节点只表达图谱抽取/索引责任而不耦合查询策略。
36. 作为最终用户，我希望图谱抽取异常不会使文本分块为空、向量索引失败或知识库节点失败，以便核心检索能力持续可用。
37. 作为运维人员，我希望能按范围观察当前版本、任务状态和失败原因，以便安全排查重建、模型和 Neo4j 问题。
38. 作为升级维护者，我希望新配置与历史图数据均由稳定版本和范围标识隔离，以便升级、回滚和定向清理可控。

## Implementation Decisions

1. **生命周期解耦**：数据集配置拆成图检索配置与图谱抽取/索引模板。图检索配置保留查询模式、图结果数量、深度、超时与权重等运行参数；抽取模板只保留抽取开关、Schema、模型与抽取参数。两个配置具有独立的验证、保存和状态语义。

2. **数据集图检索开关语义**：现有“启用 GraphRAG”字段和 UI 文案仅代表图检索。它不得要求抽取模型，也不得在切换时创建图版本、投递抽取任务或删除图数据。

3. **抽取模板持久化**：数据集级图谱抽取/索引模板需要持久化为显式配置，不得再把抽取模型混入仅用于图检索的配置验证。模板至少包含 `enabled`、Schema、抽取模型与抽取高级参数；系统计算并维护其当前 `graph_version` 与范围状态，前端不可编辑版本值。

4. **默认 Schema 常量**：首次为数据集创建抽取模板时写入以下独立常量定义的初始值，之后不自动覆盖已保存草稿：
   - 实体：`person`、`organization`、`location`、`event`、`concept`。
   - 关系：`works_for`、`located_in`、`participates_in`、`related_to`。
   - 允许三元组：`person-works_for-organization`、`person-located_in-location`、`organization-located_in-location`、`person-participates_in-event`、`organization-participates_in-event`、`organization-related_to-organization`、`concept-related_to-concept`。
   - 每个类型初始属性列表为空。

5. **抽取参数默认值**：初始草稿将 `temperature` 设为 `0`、`max_tokens` 设为未指定（使用已选模型的提供商默认输出上限）、`max_triplets_per_chunk` 设为 `10`、`strict` 设为 `true`。默认草稿中的模型为空，不能因默认值或模型列表排序而隐式选模。

6. **模型可用性**：启用或重建之前，后端以当前租户上下文校验提供商与模型仍可用于文本生成。保存的模型不可用时，系统不得自动替换；已就绪的当前图版本继续可供图检索，但任何会开始抽取或改变抽取结果的操作都返回可定位字段错误，直到用户显式选定可用模型。

7. **草稿与启用验证**：`enabled=false` 的抽取模板可持久化不完整草稿。转换为 `enabled=true` 时，必须同时验证：可用模型、至少一个实体类型、至少一个关系类型、至少一个去重且所有引用均已声明的允许三元组。类型和属性的验证遵从既有节点级 Schema 契约；失败时保持未启用，不创建版本、不清理数据、不调度任务。

8. **属性契约复用**：实体与关系类型均支持属性定义。属性逻辑名称使用 1–64 位小写 ASCII `snake_case`，说明非空，值类型为 `string`、`number`、`boolean` 或 `date`，并且在所属类型内唯一。`date` 只接受 `YYYY-MM-DD`；非法、未声明或类型不匹配的抽取值按既有规则丢弃或跳过该记录。实体属性写入 `GraphEntity`，关系属性写入 `GraphFact`，Neo4j 物理字段继续使用 `attr_<name>` 映射。

9. **默认模板快照**：当用户新启用一个 Knowledge Base 节点的图谱索引时，系统复制该时刻的数据集抽取模板为节点的初始 `graph_index_config`。复制产生独立所有权；之后修改数据集模板绝不回写已有显式节点配置。节点的正式 DSL 字段只有 `graph_index_config`，不增加 `graph_rag_config` 别名，也不批量迁移历史 DSL。

10. **节点与普通文档的配置选择**：数据集模板是普通文档范围的唯一抽取配置。发布的 Knowledge Base 节点存在显式 `graph_index_config` 时，该节点配置是其唯一抽取配置；历史节点缺少该字段时继续采用数据集级既有行为，以维持兼容性。节点配置不承载查询模式、图结果数量、深度、超时或权重。

11. **范围与版本**：抽取作用域由租户、数据集和范围标识组成；普通文档使用固定数据集范围，节点使用稳定的节点标识。首次启用以及模型、Schema、属性、允许三元组、`temperature`、`max_tokens`、`max_triplets_per_chunk` 或 `strict` 的变化都必须计算新的稳定 `graph_version`。版本指纹只使用影响抽取结果的规范化配置，不包含检索运行参数或瞬态任务状态。

12. **保存与重建状态机**：首次启用和影响抽取结果的配置保存，在事务提交后标记受影响范围为待重建并由 Reconciler 异步、分批发现历史已完成文档。保存 API 不进行同步扫描、LLM 调用或 Neo4j 写入。对同一范围，最新保存优先：先使旧版本任务失效，再清理仅属于该范围的旧版本与中间数据，最后只允许当前版本的幂等 Job 被创建、领取和写入。

13. **删除语义**：用户选择的生效语义是“先删除受影响范围的旧图数据，不保留查询回退”。删除命令必须同时按数据集、范围标识和版本条件限制；不得删除其他节点范围、普通文档范围、其他数据集或其他版本的数据。关闭图谱抽取/索引也采用该范围受限的立即清理，并阻止该范围继续产生抽取 Job。

14. **任务可靠性与隔离**：图索引继续使用独立 Job、Coordinator、Reconciler、Worker 与图存储适配层。唯一性、原子领取、失效 Job 跳过、超时恢复、最大重试和错误持久化必须按范围和版本生效。文本分块、普通向量索引与 Workflow 节点输出不能依赖图索引成功；图抽取、模型、插件或 Neo4j 故障必须只影响相应图范围。

15. **查询降级**：图检索聚合时只选择当前版本且状态为已就绪的范围。重建中、待重建、失败、禁用或模型失效但没有已就绪数据的范围不参加图检索；其他已就绪范围继续参与。向量检索、全文检索和其它已配置知识库检索保持可用。响应或页面状态必须让用户知道图检索结果可能不完整，而不是静默返回旧版本结果。

16. **界面与国际化**：数据集设置的图检索区域与图谱抽取/索引区域分别展示、分别保存。图谱抽取区域复用 Knowledge Base 节点的 Schema/属性编辑交互和模型选择能力，同时支持抽取高级参数与字段级错误。所有新增用户可见文本放入前端国际化资源，不硬编码文案。范围状态需能区分普通文档、每个节点、待重建、重建中、就绪、失败、禁用及模型不可用。

17. **安全与审计**：API 必须沿用数据集权限和租户隔离；提交的模型配置不得泄露供应商凭据。任务和范围状态保留失败原因的可诊断摘要，但日志、API 响应和页面不得暴露完整文档内容、模型密钥、Neo4j 密码或完整模型输出。

18. **迁移与兼容**：新增持久化字段、状态或索引必须通过独立、可逆迁移引入，降级只删除本需求新增对象。既有图检索配置和已发布 DSL 必须继续可读；不存在显式节点 `graph_index_config` 的历史节点不做批量写回。回滚应用版本前可关闭图谱抽取/Reconciler，任务记录作为审计数据保留，不强制清除。

## Testing Decisions

1. 测试以可观察业务行为为准：验证持久化配置、返回的字段错误、版本/任务/范围状态、查询可用范围和写入/清理边界；不测试组件内部 state 或私有辅助函数实现。

2. 后端配置契约测试覆盖：图检索与抽取配置可独立保存；首次草稿写入完整默认 Schema 和安全参数但不选择模型；未启用可保存不完整草稿；启用缺失模型、实体、关系或有效三元组时返回对应错误且无版本/任务副作用；模型失效不自动切换且阻止重建。

3. Schema 与属性单元测试覆盖：默认类型和七个允许三元组精确匹配；名称去重、允许三元组引用、属性命名、属性类型和必填语义均遵从节点级既有契约；关系属性与实体属性都能被验证和序列化；配置规范化后版本指纹在语义相同输入下稳定，影响抽取的字段变化会改变版本，检索参数变化不会改变版本。

4. 数据集 API 集成测试覆盖：读取接口同时返回独立图检索配置、图谱抽取模板和范围状态；更新任一配置不会修改另一配置；权限不足或跨租户访问被拒绝；启用成功只在提交后安排异步协调，不在请求中执行抽取。

5. 范围清理与任务测试覆盖：普通文档范围与两个不同节点范围分别创建旧数据、旧任务和新配置时，只清理当前范围；连续保存新配置使旧任务失效；重复协调只创建一个同范围同源版本 Job；过期 Worker 结果不能写入；超时运行任务可恢复；关闭抽取清除当前范围且不影响其它范围。

6. 检索测试覆盖：图检索仅使用已就绪的当前版本范围；一个范围重建中或失败时另一个已就绪范围仍参与；没有已就绪范围时走非图检索路径；关闭图检索时即使已有图数据也不调用图检索；模型失效但已有就绪数据时，图检索仍可用。

7. 文档处理隔离测试覆盖：图提取器、模型或 Neo4j 写入失败时，文本分块、普通索引、文档完成状态和 Knowledge Base 节点输出仍成功；失败原因落到图 Job/范围状态，不污染普通索引错误。

8. 前端组件测试覆盖：数据集页面明确区分两个开关；首次开启抽取显示默认 Schema 与空模型选择；未完整时不提交启用配置并显示字段错误；用户选择模型并补全 Schema 后可以保存；高级参数的默认、修改和回显正确；关闭图检索不会清空抽取模板，关闭抽取会展示受影响范围删除/重建语义。

9. Pipeline 节点前端与 DSL 测试覆盖：新启用节点取得数据集模板的一次性快照；已显式配置节点不受模板修改影响；历史缺字段节点继续走数据集级兼容路径；节点配置不序列化任何检索运行参数；属性编辑与只读版本展示继续符合既有测试约定。

10. 回归测试必须复用现有数据集 GraphRAG 配置模型、图索引 Job/Reconciler、图检索和 Knowledge Base 节点图谱配置测试切入点；新增测试应放在对应领域/组件的既有测试目录，后端使用 pytest 的 Arrange-Act-Assert 结构，前端使用 Vitest 与 React Testing Library。

11. 验收验证至少包括定向后端测试、定向前端测试、类型检查、与本需求文件相关的格式/空白校验，以及在受控环境中验证“分块和普通检索成功、图索引失败被隔离”的真实任务链路。Neo4j、模型和完整文档内容不得出现在提交日志或测试快照中。

## Out of Scope

- 自定义 LlamaIndex 图抽取 Prompt、Prompt 模板编辑器或按租户维护多个模板库。
- 自动选择、自动替换、自动降级到“第一个可用”的抽取模型。
- 为所有历史 Pipeline DSL 批量新增或迁移 `graph_index_config`。
- 将图检索运行参数写入 Knowledge Base 节点 DSL。
- 保留旧图版本作为重建中的查询回退，或跨范围查询旧版本。
- 改变既有文本分块、普通向量索引、全文检索或 Reranker 的业务语义。
- 将实体间关系改写为动态 Neo4j 关系类型，或改变 `GraphEntity` / `GraphFact` 的证据链与版本隔离设计。
- 多租户共享图谱、跨数据集图谱合并或跨节点图谱推理。
- 重新设计模型供应商凭据管理、Neo4j 基础设施或全局 GraphRAG 环境开关。
- 在本规格阶段执行代码实现、数据库迁移、提交、推送或部署。

## Further Notes

- 新需求的默认 Schema 适用于通用文档，替代此前仅面向产品/模块等技术资料的默认词表作为“首次启用数据集抽取模板”的初始值；既有已保存的配置不做隐式改写。
- 图谱抽取和图检索的可观测状态必须按范围呈现，而不是以单个数据集布尔值掩盖节点/普通文档之间的不同进度。
- 当前仓库没有可用的项目 issue tracker 集成，故未执行外部发布；本文件以及同日 ADR、决策记录和编排状态是可审计的本地正式产物。
- 后续拆票应先处理配置契约/迁移、数据集 UI、节点模板快照、版本与范围清理、任务可靠性、查询降级和覆盖测试之间的依赖关系，避免先接入抽取而没有范围隔离与失败隔离。
